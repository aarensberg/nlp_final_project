Baseline : TF-IDF + régression logistique

Ce que c'est

  • Vecteurs TF-IDF sur unigrammes et bigrammes
  • Régression logistique sur les 100 types
  • ≈ 4 min d'entraînement sur CPU

Pourquoi il est difficile à battre

Sur LEDGAR, le type d'une clause tient souvent à quelques mots-clés : « governing law », « counterparts », « severability ». Un modèle lexical les capte très bien.

Usages autorisés et interdits

Usage prévu

  • Aide au tri de clauses anglaises de type SEC
  • Relecture humaine systématique
  • Clauses sous le seuil → juriste
  • Recherche de précédents comme point de départ

Ne pas utiliser pour

  • Décider seul du type ou de la portée d'une clause
  • Le droit européen, le français, l'allemand : non validé
  • Détecter exhaustivement risques ou clauses abusives
  • Les types absents : RGPD, force majeure, limitation de responsabilité…
  • Retrouver un préavis précis : filtre non sémantique
  • Conclure sur l'équité envers des personnes : proxys
Classer un type de clause n'est pas juger sa validité juridique.

Limites et suite

Limites mesurées

  • BERT seul sous TF-IDF ; combinaison ≈ +0,7 pt
  • Labels quasi synonymes : Applicable Laws / Governing Laws, Waivers / No Waivers
  • Clauses de bail et classes rares
  • Recherche : la notion de préavis n'est pas comprise
  • Une graine, une machine, Python bêta

Suite proposée (non réalisée)

  • Expérience contrôlée : 256 vs 512 tokens, 2 vs plus d'époques avec arrêt anticipé, plusieurs graines
  • Clauses européennes annotées, types manquants
  • Extraction structurée des délais (rôle + durée + type de jours)
  • Fusion des quasi-synonymes validée par des juristes
